# Sign2Voice: project summary (for application use)

**One line.** A real-time ASL fingerspelling recognizer (MediaPipe hand landmarks → small 1D-CNN → speech) that I originally
reported at 99.15 % accuracy, then re-audited, re-measured honestly, and extended with a robustness study.

## What I built
A final-year project: webcam → MediaPipe Hands (pretrained) → 21 landmarks (63 numbers) → a 589,852-parameter Conv1D classifier
that I trained from scratch on the Kaggle ASL Alphabet dataset (28 classes) → text and text-to-speech, with a desktop GUI and
a MERN web app (accounts, saved transcripts). Word suggestions use a pretrained distilgpt2, unmodified.

## What I found when I audited it
1. **The headline number was inflated.** 99.15 % came from a random split of consecutive video frames, so
   near-duplicate frames sat on both sides of the split. A leakage-aware split (contiguous blocks per class, with a gap) gives
   **96.7 ± 0.5 %**. A random split in my reproduced pipeline still gives 98.9 %, which is consistent with the gap coming from the split (I did not isolate it further).
2. **It does not generalize to new people or cameras.** On a second public dataset with 5 other signers: **71 ± 2 %**. On my
   own webcam recordings (one person, two lighting setups): **45-51 %**. Several letters get zero recall on these sets.
3. **Security and hygiene problems in the original repo**, fixed: hard-coded admin password, a JWT secret that silently fell
   back to `"secret"` (an import-order bug), an unauthenticated endpoint that launched a process, thousands of committed
   dependency files.

## Robustness study (landmark-space threat model)
White-box FGSM and PGD (L∞ and L2) on the 63-d input, natural perturbations (rotation, tilt, jitter, dropped landmarks), and two
defences, 3 seeds each, identical splits per seed:

| Model | Clean | PGD ε=0.01 | PGD ε=0.02 | Rotated 45° | 5 other signers |
|---|---|---|---|---|---|
| Baseline | 96.7 | 60.8 | 18.3 | 33.7 | 71.1 |
| Rotation/scale augmentation | 96.6 | 60.3 | 20.6 | 86.9 | 73.1 |
| PGD adversarial training | 96.5 | 88.7 | 71.0 | 35.1 | 75.5 |
| Both (shipped) | 95.9 | 88.2 | 70.2 | 83.5 | 78.1 |

* Adversarial training and augmentation fix **different** failures and combine well, for about 0.8 points of clean accuracy.
* The defences do **not** fix the real-world gap: webcam accuracy stays near 45-54 % with every variant. My hypothesis that
  rotation explained it was tested and rejected; the cause is still open (signer differences, camera/pose conventions, label
  conventions).

## What I would say about the limits
* Webcam test data is from one person; it measures setup robustness, not signer generalization.
* Attacks are PGD-20 on a 5,000-sample subset, in landmark space only; MediaPipe is not attacked, no adaptive attacks or certification.
  The robust-accuracy numbers are upper bounds.
* The block split assumes Kaggle image numbers follow video order; I did not verify this.
* J and Z are motion letters evaluated on single frames.

## What I learned (usable in a statement)
* How easily a strong-looking benchmark number can be an artifact of the split, and how to design and test a leakage-aware one.
* To report effect sizes with seeds and error bars, and to state a threat model before attacking a model.
* Verifying the whole path (running the web app and GUI end to end) found five bugs that code reading had not.
* A negative result (rotation does not explain the real-world gap) is worth reporting.
